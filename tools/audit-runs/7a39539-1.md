## Findings

### 1. The short adds a claim (meaning changed)
- File: lessons/physics/p2-current-voltage.json
- Field: keyPoints[0].widget.options.predicts[0] (cv-loop).options[1].short
- Old text: "Yes: the cell sends electricity along the wire to the lamp"
- New text: "Yes, brightly"
- Fault: The full option says only that the lamp lights. The short adds "brightly". A student who thinks the lamp lights, but is unsure how brightly, is now pushed towards "Yes, but only dimly". Both are M1, so the code recorded is the same. But the short is a different prediction from the full text. "Yes, it lights" would keep the meaning and still differ from option 2.
- Evidence: lines 292-294.

### 2. The M2 short is weaker than the misconception it records
- File: lessons/physics/p2-current-voltage.json
- Field: keyPoints[0].widget.options.predicts[1] (cv-same-current).options[1].short
- Old text: "Ammeter 2 reads less: the lamp uses up some of the current"
- New text: "Ammeter 2 reads less as the lamp uses current"
- Fault: M2 is that current is USED UP. The short drops "up", and "uses current" is ordinary, correct language (a lamp does use a current). The misconception is still carried by "reads less", so this is minor, but the defining words are gone. Also, "as" can be read as "while" as well as "because", which is unclear for a 15-year-old. The same applies to options[2].short, "Ammeter 2 reads less as it is further round". Suggest "Ammeter 2 reads less: the lamp uses some up".
- Evidence: lines 337-339, 342-344. The wording elsewhere in the lesson is "charge is not used up" (KP1 content line 49, explain point line 362).

### 3. A missing tryShort means the answer can leak in the components widget
- File: lessons/physics/p2-components.json
- Field: keyPoints[0].widget.options.predicts[0] (comp-same-circuit).tryShort
- Old text: (none)
- New text: (none). needs and controls were added, but tryShort was not.
- Fault: Every predict in current-voltage KP1 and KP2 got a tryShort. This one did not. If the AI lesson falls back to try, the student sees "...but it is the same loop: the ammeter and the lamp do not change". That states the correct option ("They are the same circuit") inside the instruction. Check (3) also cannot be run on it.
- Evidence: line 196, compared with lines 204-206.

### 5. cv-voltmeter needs uses a code outside the stated set, and lists two controls
- File: lessons/physics/p2-current-voltage.json
- Field: keyPoints[1].widget.options.predicts[1] (cv-voltmeter).needs
- Old text: (none)
- New text: ["add", "remove"]
- Fault: (a) "remove" is not one of the documented needs codes (sw, add, res, run, redraw), although it is in controls. (b) needs is described as THE control the student must use, but two are listed. If the code reads this as "both required", it conflicts with tryShort "Add a cell OR take one away". (c) setup is cells: 1, so "take one away" would leave no cell, if the widget even allows that [not verified]. (d) Neither control tests the prediction cleanly. Adding a cell raises both meter readings together, so the voltmeter-versus-ammeter distinction comes from the meter labels, not from the action. That last point is about the test design and was already in the old try.
- Evidence: lines 666-669, 678-682, 731-736.
